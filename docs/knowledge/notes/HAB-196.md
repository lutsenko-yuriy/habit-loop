## Debrief summary

### 2026-07-25

**What went well**
- Validating every fix attempt against a live `scenarios.yml` dispatch before keeping it — this caught two plausible-looking but wrong hypotheses (a keyboard-settle pump, a redundant-invalidation removal) before either shipped, and meant every fix that landed in the PR was actually proven against real CI behaviour, not just code reading.
- Switching to temporary `print()` diagnostic instrumentation once static code reading stopped producing reliable answers. Reading the code suggested plausible mechanisms twice and both were wrong; adding targeted prints and dispatching live gave real data that either confirmed or (twice) cleanly disproved a hypothesis before more time was sunk into it.

**What was hard or surprising**
- Two hypotheses that read as very plausible from the code turned out to be wrong once validated live — static reading alone wasn't a reliable signal for this class of bug (CI-only integration-test failures), even when the reasoning behind the hypothesis seemed sound.
- The full scenario suite takes ~10 minutes per dispatch, and the diagnostic/fix/validate loop ran roughly 9 times across this ticket — each iteration paid the full-suite cost even when only one test file's outcome mattered. Filed as HAB-197 to add scenario-level filtering to `scenarios.yml`.
- Mid-debrief, defaulted to structured multiple-choice questions (`AskUserQuestion`) for open reflective questions ("how did it go", "what else stood out") instead of plain free-form text — added friction the user hadn't seen in prior sessions' dialogs.

**What to change**
- File CI-scoped follow-up work like scenario filtering as its own ticket at debrief time rather than trying to fold it into the debrief's own file-change step — it's infrastructure work, not a workflow/skill doc edit.
- Default to free-form text for open/reflective dialog questions; reserve structured multiple-choice for genuine forks with discrete, enumerable options. Added to `skills/shared/dialog-guidelines.md`.
