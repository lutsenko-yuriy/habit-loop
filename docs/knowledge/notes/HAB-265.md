# HAB-265: notification_navigation_flow_test.dart still asserts "Pending" text after HAB-263 changed dashboard subtitle to uiState-specific text

## Notes

## Debrief summary

### 2026-09-03

**What went well**
- Root cause was identified, fixed, and locally verified quickly — going straight from CI failure logs to the exact commit and line that changed the dashboard subtitle text.

**What was hard or surprising**
- The regression had been sitting on `main` for a full day (since HAB-263 merged) before it surfaced — and it surfaced only by accident, while investigating an unrelated flakiness ticket (HAB-258). HAB-263's own PR never dispatched `scenarios.yml`, because its diff only touched `lib/` (a shared formatter) and not `integration_test/` — the review loop's dispatch-gate trigger condition (`docs/workflows/FEATURE.md` step 10.6) only fires on `integration_test/` changes, so a production-only change that breaks existing scenario coverage can merge with zero scenario verification.

**What to change**
- Broadened `docs/workflows/FEATURE.md` step 10.6's scenario-dispatch trigger from "PRs that touch `integration_test/`" to "PRs that touch `lib/` or `integration_test/`" — any app-code change now gets scenario-checked before merge, closing the exact gap that let this regression through undetected.
