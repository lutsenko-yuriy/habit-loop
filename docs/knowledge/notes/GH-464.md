Tracked as GitHub issue #464 (Linear free-plan issue limit reached). Plan: issue comment 6112401841; decisions: comment 6112490321.

## Notes

### 2026-10-11

**WU scope summary**

- Research — check that `app_links` works with UIScene/`FlutterSceneDelegate` on Flutter 3.44, the built-in deep-link opt-out keys, and the `canLaunchUrl` package-visibility rules. Findings go in this note; no branch.
- Scenario — S1–S14 integration scenarios plus `FakeChecklisterGateway`/`FakeIncomingLinkService` hooks in `AppHarness` (`[test]` PR).
- WU1 — domain models (`PactChecklistLink`, `ChecklistRun`, gate/derivation), repositories, schema v8 with two additive local-only tables (cascade on delete).
- WU2 — `ChecklisterGateway` (`url_launcher`), installed check, kill-switch `checklister_integration_enabled`, `has_checklister_installed` user property, iOS/Android query declarations.
- WU3 — incoming `habitloop://` links (`app_links` or channel fallback), callback parser, built-in deep linking disabled, callback navigator skeleton.
- WU4 — pact-detail checklist section (select/change/remove) with its own view model, plus selection-callback handling and l10n.
- WU5 — showup-detail gate and "Run checklist" (persist `startedAt` before launch), `checklist_outcome` on mark-done.
- WU6 — run-finished callback, failure dialog, late-finish exemption from auto-fail (detail + dashboard sweep).
- WU7 — Siri gate in Swift, PRODUCT_SPEC/ARCHITECTURE updates, release version, `[user]` CHANGELOG.

**User decisions that reshaped the brief/plan**

- Selecting a checklist during pact creation was dropped mid-brief: it needs a callback URL, and the wizard has no way to receive one. Selection lives only on pact detail, for active pacts.
- "Don't change existing entities if possible" — so the link and run state are stored in new tables, and `Pact`/`Showup`/sync are untouched.
- Checklister has no "failure" status, only `completed`/`cancelled`/`error`. The user chose to treat `cancelled` and `error` as unsuccessful.
- Late-finish grace period cut from the proposed 60 to **15 minutes**.
- No backend sync for links/runs, and no confirmation on "Remove".
