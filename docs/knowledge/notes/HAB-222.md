**The chat markdown block is model input, not just human output**

`format_linear_context`'s markdown is prepended to the LM Studio prompt in `scripts/skill_router/app.py:65`. The ticket left "is the chat summary fully replaced or kept alongside the HTML view?" open, but the architecture forces the answer: replacing it with a pointer to `backlog.local.html` would leave the model with no backlog data at all, so it could not answer "what goes into the next release?" or any follow-up. Chat output stays byte-identical; the HTML is strictly additive. Worth remembering generally — anything that looks like "session-start chat formatting" in this repo is actually prompt construction.

**A ticket's own out-of-scope list can be internally inconsistent**

The ticket asked for the `#` column to link to the Linear issue URL *and* declared "no new GraphQL fields" out of scope — but `ISSUES_QUERY` never fetched `url`. The two requirements could not both hold. Planning surfaced it and offered both routes (construct the URL from a configured workspace slug vs. add the one field); the user chose adding `url`, which deleted an entire config-plumbing strand from WU2 (`config.py`, `app.py`, `skill_router.toml`, a `LINEAR_WORKSPACE_SLUG` env var, and a `workspace_slug` ctor kwarg). Checking each out-of-scope bullet against what the in-scope behaviour actually requires — before drafting around the constraint — was worth roughly 40 LoC and four fewer files touched here.

**The HTML path exists on only one of `/summarize`'s two execution paths**

`/summarize` runs either through the `skill_router` Python pre-fetch or, when that exits non-zero, through a live-MCP fallback inside Claude Code (`.claude/commands/summarize.md`). Only the Python path can generate the file. The asymmetry is deliberate — hand-writing the HTML in the fallback would cost more than it's worth — and is documented in SKILL.md as part of WU2 so it doesn't later read as an oversight.

**Pre-existing gap found: `scripts/skill_router/` is absent from `docs/ARCHITECTURE.md`**

The `scripts/` table lists every other script package but has no row for the router, despite it being the entry point for most slash commands. Folded into WU2 rather than deferred, since the WU already had to touch that table.

**A side effect wired into a shared method leaks to every caller of that method**

WU2's first PR draft put the HTML-render/write/open side effect directly inside `LinearProvider.format_context` — reasonable-looking, since that's the method `summarize` calls. But `format_context` is shared: `draft-scenarios` also declares `context: linear` and calls the exact same method, so it would have inherited the same browser-popping side effect mid-ticket, completely unrelated to what it actually needed. Caught in `audit-code`'s first pass on PR #378, not in planning or architectural review. Fixed by reverting `format_context` to pure markdown and moving the side effect to a new opt-in `render_backlog_view` method, gated by a `render_html_view: true` frontmatter flag that only `summarize` sets. General lesson: when a new side effect is being wired into an existing method, check every caller of that method, not just the one motivating the change.
