# HAB-221: Tagged table of contents for docs/knowledge/notes/ to mine historical pain points

## Notes

### 2026-08-11

**WU scope summary (plan approved)**

- **WU1 — Index generator + tests + template frontmatter.** `scripts/notes/index.py` (generate/`--check`/`--apply-bookmarks`), `scripts/notes/tests/test_index.py`, frontmatter added to `TEMPLATE.md`, skeleton `BOOKMARKS.md`, `docs/ARCHITECTURE.md` updated. Builds the tooling against an empty/partial corpus before touching real notes.
- **WU2 — Corpus backfill.** One read-through of all 64 existing notes produces a bookmark map, applied mechanically to every file (frontmatter only, no body edits) plus the first real `INDEX.md`/`BOOKMARKS.md`. Deliberately touches 65 files — flagged as an exception to the ≤10-files guideline since it's purely mechanical, reviewable as a diff shape (like a `dart format` commit).
- **WU3 — Keep it from decaying.** Write-time bookmarking added to `/note` and `/debrief`, a quarterly re-bookmark dimension added to `/checkup heavy`, a **blocking** `--check` step wired into CI (`run-tests`), and docs (`docs/knowledge/README.md`, `AGENTS.md`) updated.

**Key decisions from planning dialog:**
- Frontmatter (not a sidecar file) — tags travel with the note content.
- Named **bookmarks**, not tags — avoids colliding with the CHANGELOG tag taxonomy.
- No upfront taxonomy — vocabulary (`BOOKMARKS.md`) emerges from one read-through of the corpus.
- Missing `bookmarks:` key vs explicit `bookmarks: []` are different states: missing = not yet processed (fails `--check`), empty list = reviewed, deliberately nothing noteworthy (passes).
- `--check` is blocking in CI, not advisory — enforces "can't silently drift."

All three WUs are `[wip]`/`[meta]` — no `pubspec.yaml` bump; everything lands under `## [Unreleased]`.

### 2026-08-12

**WU3 review findings**

- WU1's plan said "frontmatter added to TEMPLATE.md" but that step was actually skipped — `TEMPLATE.md` had no frontmatter block at all until this WU's audit pass caught it. Any note created via `/plan`'s WU-scope-note step (not just `/note`/`/debrief`) would have failed the new blocking `--check` at CI time. Fixed by giving `TEMPLATE.md` a fail-safe `bookmarks: []` default.
- Audit flagged a real merge-race risk: `INDEX.md` is generated *and* committed, so two branches independently bumping the same bookmark's count can merge cleanly to a stale-but-internally-consistent value that still passes `--check`. Deferred as [[HAB-223]] rather than fixed inline — the two candidate fixes (custom git merge driver, or regenerating at `/ship` time) both touch files outside WU3's scope and need their own design pass.
- Separately: the `implement` skill's LM-Studio-driven `skill_router` path produced a real bug mid-run on this WU (an unrelated `coverage/lcov.info` → `lcv.info` typo in `.github/actions/run-tests/action.yml`) before timing out incomplete. Discarded that draft and redid WU3 by hand.

### 2026-08-12 (continued)

**Kill switch shipped inert — caught by re-audit**

- The debrief's own fix (disabling `skill_router`'s local-model route) shipped with a real bug: every `.claude/commands/` stub invokes bare `python3`, which on this machine (and any Python < 3.11) has no `tomllib`. `_load_toml` silently returned `{}` in that case, so `local_models_enabled` fell through to its `True` default and the kill switch never fired on the actual invocation path — verified live before the fix.
- Fixed by making `_load_toml` distinguish "genuinely absent file" (fine, defaults apply) from "exists but couldn't be parsed" (fail closed — `local_models_enabled=False` — plus a loud warning). Also closes the adjacent long-standing HAB-176 silent-`{}` gotcha for every other toml-backed setting.
- Lesson: a re-audit after "just a config flip" landed a second real bug in the same PR — worth keeping the re-review-after-non-trivial-changes discipline even when a change looks purely additive.

## Debrief summary

### 2026-08-12

**What went well**
- The ticket overall — corpus tagging, tooling, decay prevention all landed as planned across the three WUs.

**What was hard or surprising**
- Running local models (LM Studio, feeding `skill_router`) turned out to be a heavier load on the laptop than expected, on top of the reliability problems that already surfaced mid-WU3 (a real bug + an incomplete timeout).

**What to change**
- Disabled the local-model route entirely for now: `skill_router.toml`'s `[core] local_models_enabled = false` makes every `skill_router` invocation exit 1 immediately, so each `.claude/commands/` stub's existing cloud fallback kicks in uniformly — no per-stub changes needed.
- Opened HAB-224 to research fitting hardware and how to connect a remote local-model host to this session, before reconsidering re-enabling it.
