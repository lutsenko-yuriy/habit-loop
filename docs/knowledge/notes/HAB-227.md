# HAB-227: Break-over "welcome back" reminder text

## Notes

<!-- Each entry: dated heading, then named observations (bold title + paragraph).

### 2026-08-15

**Self-caught bug before audit posted**

While writing the architectural review for PR #380, found that `FeatureFlags.breakWelcomeBackNotificationEnabled` was wired through HAB-207 release-version gating but never actually consumed — `ReminderSchedulingService` reads the raw RC value directly, matching its sibling keys. Fixed (commit `2c82da5`) before `audit-code` even ran, which then independently flagged the same field as dead weight.

**Audit surfaced a real, narrower gap: HAB-234**

`audit-code` found that two existing call sites (`pact_edit_view_model.dart`, `language_picker_handler.dart`) called `scheduleRemindersForShowups` without `breaks:`, silently dropping both on-break suppression (a pre-existing HAB-195 blind spot) and this ticket's welcome-back text. Fixed in-PR with tests. A deeper edge case — a proactively-scheduled reminder for a not-yet-persisted showup escaping a later, unrelated break's cancellation sweep, plus a related multi-device staleness case — was judged too large a design change to rush into this PR and was split out to HAB-234 instead.
