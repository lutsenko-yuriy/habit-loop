# HAB-189: CI/lint check for raw spacing literals instead of AppSpacing tokens

## Notes

## Debrief summary

### 2026-08-16

**What went well**
- Ticket was fully spec'd (exact behaviour, root cause, recommendation) so implementation went straight to TDD, no `/plan` pass needed.
- Checked the real repo before assuming a design — confirmed 0 outstanding raw literals besides the one known exception, so the lint could hard-block CI immediately with no baseline/grandfather mechanism.
- Three real audit rounds, each catching genuine bugs that compounded on the fix from the round before: round 1 found the naive non-nested regex silently missed real violations whenever a call had *any* nested parens; round 2 found comment/string content wasn't masked (false positives) and the fix for round 1 itself needed masking to be safe; round 3 found block comments specifically weren't masked, named constructors (`SizedBox.square`, `EdgeInsetsDirectional`) bypassed the gate entirely, and stale allowlist entries had no drift detection. Each round's fix was verified with new regression tests and a live re-scan of the real repo.
- Mid-review pivot from inline `// spacing-lint: allow` suppression comments to a single checked-in `spacing_allowlist.txt` — user's call, cleaner for application code, and ended up enabling the round-3 stale-entry detection feature that inline comments couldn't have supported as naturally.

**What was hard or surprising**
- Observed and discussed: `audit-code` has been catching real bugs on every recent PR (HAB-223, HAB-184, HAB-189), while `review-architecture` finds little to nothing on scripts/CI-only tickets — because `architectural-checks.md` is written entirely in Flutter layer/dependency-direction terms, so it has almost no native checklist to apply to Python tooling. Logged as evidence on HAB-225 (already-open research ticket on whether `scripts/` needs its own review lens) rather than opening a duplicate.
- Also surfaced: no existing mechanism for batching several tickets into one release — every `/ship` is its own micro-release today. Filed as HAB-240 (research, scoped for both current solo-dev-plus-agents reality and a hypothetical ≤6-dev+PO+QA team).

**What to change**
- Nothing actioned directly in this ticket — both observations above are captured as follow-ups (HAB-225 comment, new HAB-240) rather than scope-crept into HAB-189 itself.
