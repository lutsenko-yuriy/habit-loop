# GH-474: Flaky text-entry scenarios on CI (pact note, display name)

## Notes

### 2026-10-13

**Root cause: the real IME stays attached during scenarios**

- `IntegrationTestWidgetsFlutterBinding` sets `registerTestTextInput => false`, so `tester.enterText` injects text while the device keyboard stays connected without knowing about it. Its next stale update can revert the field. Flutter's `TestTextInput.updateEditingValue` docs warn about exactly this.
- The symptom matches every logged failure: the text reverts to the saved value (Save never enables, the name stays 'Alex').
- Fix: `AppHarness.create` registers `tester.binding.testTextInput` per test and unregisters it on teardown. The real keyboard never appears.

**Dead end: a custom binding subclass**

- A `HarnessBinding` with `registerTestTextInput => true` fails every run with "Binding is already initialized to IntegrationTestWidgetsFlutterBinding". `flutter test`'s generated entrypoint creates the stock binding before the test's `main`. Reverted.

**Verification**

- Locally on Pixel_5_API36: `pact_note_flow_test` and `display_name_flow_test` each passed 5 of 5.
- CI: `scenarios.yml` passed 3 of 3 dispatches (38442988989, 38444490932, 38446213855). The ticket logged 3 of 3 failures before the fix.

**Folded in: `stop_pact_flow_test` failed every time locally**

- `scrollUntilVisible` stopped with "Stop Pact" at y=874 on an 851-px-tall viewport. It fails 3 of 3 on `main` too, so it predates this change, and it passes on CI. Fixed with `ensureVisible` and `pumpAndSettle` before the tap. The user chose to fold it into this PR.

**Coverage trade-off (accepted when picking option 1)**

- The fake keyboard takes no screen space, so no scenario exercises the keyboard-open layout (`viewInsets.bottom`). Bugs like HAB-199's button-under-keyboard now need widget tests with a non-zero `viewInsets`, or an opt-out scenario using the real keyboard.

**Still open**

- The full local suite also hit the known ambiguous-`ListView` finder in harness `openTimeline` (GH-464 WU5 notes) once. It passed 3 of 3 in isolation. Not fixed here.
- Keyboard-animation workarounds in break/create/edit/timeline/pact-note scenarios may now be dead code. That cleanup is a follow-up candidate.
