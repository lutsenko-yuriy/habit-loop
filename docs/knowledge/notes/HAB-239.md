# HAB-239: CI/lint check for raw TextStyle/fontSize literals instead of AppTypography tokens

## Notes

## Debrief summary

### 2026-08-17

**What went well**
- Ran start-to-finish (branch, TDD, real-repo baseline check, PR, review loop, fixes) without needing the user's participation until the review sign-off — the only mid-flight input needed was one design decision (how strict the duplicate-detection rule should be, given the codebase's baseline wasn't clean the way HAB-189's spacing baseline was).

**What was hard or surprising**
- The PR ended up sized like a new-screen feature, but in Python — a "completely different stack" from the Flutter/Dart work the size gates and conventions were built around.
- The user isn't proficient enough in Python to review the diff manually, so `review-architecture`/`audit-code` effectively became the *only* review — and did catch two real correctness bugs (a signature-collision dict silently dropping a token name, and a fixed property shortlist causing false-positive duplicate flags), which is exactly what should happen when the human safety net is thin.

**What to change**
- Confirmed the premise of HAB-225 (does `scripts/` need its own implement/review loop?) — the answer is yes. Narrowed HAB-225 to the *how* instead of the *whether*.
- Opened three new research tickets: HAB-242 (orchestrating multiple sub-projects — Flutter app + Python/Bash tooling — sharing one repo), HAB-243 (how to run a project when goals are clear but the stack/approach isn't), and HAB-244 (trade-offs of keeping `scripts/` in this repo vs. splitting it into its own — conceptually upstream of HAB-225 and HAB-242, since the repo-boundary decision may reshape both).
