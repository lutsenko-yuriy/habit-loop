By sub-question:
- **Comment density/length** — thin. Nothing gives a checkable number; only qualitative "brevity." No usable external threshold exists to cite.
- **Function/class size** — best covered but contested. DCM (Dart-specific, directly enforceable), ESLint, and SonarQube's default converge in the same order of magnitude (~15 complexity / ~50-60 LOC). The famous Clean Code "20 lines" figure is unverified; McConnell's actual data complicates the "shorter is always better" story.
- **PR/CL size** — well covered, two independent traditions agree in direction: Google (~100 lines reasonable, 1000 too large) and Cisco/SmartBear (200–400 LOC/session) — different exact numbers, same shape, both checkable.
- **File/module span per PR** — thin. Only one illustrative Google example, no stated rule.

Gaps flagged explicitly: sub-questions 1 (comments) and 4 (file span) have no real threshold anywhere in the literature found. Two of the most commonly *quoted* figures elsewhere (Clean Code, SonarQube default) are the least verified sources in this pass.

**Comment framing candidate — "lecture notes," not narration**

Since no external source gives a checkable comment threshold, the user proposed a framing to carry into the follow-up ticket instead of a numeric rule: write WHY-only comments the way a student writes lecture notes on math (or any dense subject) — concise, often using shorthand/notation, but complete enough that nothing necessary is missing. The target isn't "shortest possible" (which risks losing the WHY) or "explain everything" (narration, already forbidden) — it's *information-dense and self-sufficient*: a reader with the right background reconstructs the full reasoning from the note alone, in one pass, with no filler. This reframes brevity from a length limit to a density/completeness bar, which is closer to what [[feedback_code_comment_brevity]] and repeated review feedback (HAB-234, HAB-207/208) have actually been pushing for than any LOC-style cap would be. Candidate only — not adopted here; the follow-up ticket (out of scope for this research-only ticket) decides whether/how it lands in `docs/CODE_STYLE.md`.
