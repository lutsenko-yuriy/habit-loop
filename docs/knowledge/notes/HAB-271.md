# HAB-271: Bug: app fails to relaunch after force-quit — splash screen flashes and closes (Debug only)

## Notes

### 2026-09-08

**Root cause confirmed: upstream Flutter engine limitation, not an app bug**

Reproduced via a real device (not the flutter tool's resident session, to remove the
debugger-attached masking effect): installed a Debug build with `flutter install`, then
cold-launched it with `xcrun devicectl device process launch` (no debugger attached — the
same condition as tapping the icon after a force-quit). The app crashed immediately;
pulled the actual crash report off the device with
`xcrun devicectl device info files --domain-type systemCrashLogs` +
`device copy from`.

Crash: `EXC_BAD_ACCESS` / `SIGSEGV` at `0x0`, thread 0 (main):
```
-[VSyncClient initWithTaskRunner:callback:]
-[FlutterViewController createTouchRateCorrectionVSyncClientIfNeeded]
-[FlutterViewController viewDidLoad]
-[UIViewController _sendViewDidLoadWithAppearanceProxyObjectTaggingEnabled]
... -> UIWindow _mainQueue_makeKeyAndVisible
```

This is a byte-for-byte match to a known, unresolved upstream issue:
[flutter/flutter#183900](https://github.com/flutter/flutter/issues/183900) and
[#153971](https://github.com/flutter/flutter/issues/153971). Root cause (per the Flutter
engine team): on ProMotion devices, `viewDidLoad` fires before the implicit Flutter
engine finishes attaching its task runner to the view controller, so `VSyncClient`
dereferences a null pointer. An attached debugger (`flutter run`/Xcode) happens to slow
process startup enough to avoid the race; an untethered cold launch does not. A Flutter
maintainer states plainly: *"Launching Flutter iOS apps that were built in debug mode
from cold start is not supported currently."* A defense-in-depth engine PR
([#184639](https://github.com/flutter/flutter/pull/184639)) was opened but the issue was
closed unresolved — no shipped fix as of this writing.

Confirmed **Debug-only** — multiple reporters on the upstream thread confirm Release
builds launch fine; this app's own `AppDelegate.swift` uses the exact affected pattern
(`FlutterImplicitEngineDelegate`). This is very likely also the true explanation for
HAB-55's original symptom (Debug-only `EXC_BAD_ACCESS` on cold start), which was
"resolved" by a Flutter upgrade that likely just shifted the race window rather than
fixing a real app-code bug — worth keeping in mind if a similar symptom resurfaces again
after a future Flutter upgrade.

**Decision:** documented and closed with no code change (user's call, given Low priority
and zero Release/TestFlight impact). The available workaround — switching `AppDelegate`
from the implicit-engine pattern to explicit `FlutterEngine` creation — is a real
architectural change to app boot, for a benefit limited to local Debug testing on
ProMotion devices. Not worth it at this time.

**Practical takeaway for local dev:** on a ProMotion device (iPhone 14 Pro/15 Pro/16 Pro
or later), a Debug build force-quit from the App Switcher and relaunched by tapping the
icon will crash on relaunch — this is expected and not a real bug. Relaunch via
`flutter run`/Xcode instead when testing that flow.
