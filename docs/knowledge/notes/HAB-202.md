- **WU3 — detail read-side + feature toggle** (`[wip]`). Load predecessor + successor into `PactDetailState`/ViewModel; render "Previous Pact" (under name/badge) and "Next Pact" (bottom area) links on both platforms with navigation; `PactChainLinkTappedEvent`; new Remote Config kill-switch `pact_chaining_enabled` (default `true`) gating button + links, documented in `docs/FEATURE_TOGGLES.md`; l10n. Link rendering covered by widget tests.
- **WU4 — "Adjust and start again" action** (final WU → `[user]`). Button on finished pacts (both platforms) in the bottom action spot, `_onAdjustAndStartAgain` (build prefill via `PactChainService`, seed config, push `PactCreationScreen`, reload on return), `PactAdjustAndStartAgainTappedEvent`, `PactWizardAbandonedEvent` `source`. Drives all end-to-end chain scenarios green.

**Cross-WU invariant reminders**

- "At most one successor" is enforced at the data layer (partial unique index + `savePact` guard), not just by hiding the button — per the approved architectural decision.
- The version-number default name is computed once at creation from the chain root, never recomputed; renaming any pact later does not retroactively change others.
- No stats/streak carryover — the chain is purely navigational/informational.
