### 2026-08-04

**WU scope summary (plan approved)**

- **WU0 — scenarios** (`feature/HAB-213-WU0-scenarios`, `[test]`): red integration scenarios only — S1 `overflow_dot_not_blue_when_only_some_showups_on_break` in a new `integration_test/showup_on_break_flow_test.dart`, S2 `onbreak_showup_detail_hides_done_failed_actions` appended to `integration_test/break_flow_test.dart` (it already opens an on-break showup's detail). Locks both observable behaviours before any production code moves.
- **WU1 — overflow-dot fix** (`feature/HAB-213-WU1-overflow-dot`, `[wip]`): `ShowupStatusColors.overflowForUiState` only — on-break wins the overflow dot only when *all* that day's showups are on break (`uiStates.isNotEmpty && onBreakCount == uiStates.length`; the `isNotEmpty` half keeps an empty list falling through to `done` as today). Three existing tests assert the old "any on break" rule and are rewritten, not deleted: `showup_status_colors_test.dart:115` and `:154`, `showup_status_dots_test.dart:125`.
- **WU2 — hide actions on break** (`feature/HAB-213-WU2-hide-actions`, `[wip]`): one gate in the shared `ShowupDetailContent` — `isPending && uiState != ShowupUiState.onBreak` — so Done/Failed disappear entirely while on break, the "On break" badge carrying the state alone. Neither platform page changes (they only supply the slot), and no view-model/state change is needed since `state.uiState` already carries `onBreak`.
- **WU3 — animate the detail screen** (`feature/HAB-213-WU3-animate-detail`, `[user]`, version bump, `/debrief` before `/ship`): six presence toggles in `showup_detail_content.dart` become `AnimatedReveal` (each block's spacer moved inside so the gap collapses with it), and the `StatusBadge` crossfades via `AnimatedValueTransition` pinned to `StatusBadge.widestOf` so "Pending" → "On break" doesn't shift the Row. Watch the callback-nullability trap: `onStartBreak`/`onOpenPact` go null exactly when their block starts collapsing, so the revealed child must remember the last non-null callback (the `BreakBannerReveal` shape).

Primitive choice: `AnimatedReveal` for presence, `AnimatedValueTransition` for the badge swap — approved over the ticket's original `AnimatedSize` wording, pending seeing it in practice. `AnimatedValueTransition` needs a caller-supplied `previousChild`, so it fits a value swap but not a show/hide; `AnimatedReveal` is already the pact detail screen's treatment for this same class of blocks, and its doc comment records that `AnimatedSize`-around-`AnimatedSwitcher` was tried there first and gave fade-then-shift. No new primitives, no new feature toggle (`pact_breaks_enabled` already covers on-break display), no new analytics events, no `docs/ARCHITECTURE.md` change (all four primitives already documented there).
