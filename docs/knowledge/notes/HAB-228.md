### 2026-08-15

**docs/ARCHITECTURE.md's notification-ID description is stale**

`docs/ARCHITECTURE.md:141` says notification IDs derive from `scheduledAt.millisecondsSinceEpoch ~/ 1000` — the actual scheme (`lib/infrastructure/notifications/contracts/notification_constants.dart`) is an FNV-1a 32-bit hash of `showupId`, split into disjoint reminder/deadline ranges. Needs a follow-up doc fix; unrelated to this ticket's scope so left alone here.

## Debrief summary

### 2026-08-15

**What went well**
- The bulk of implementation (viewmodel, both platform screens, tests, review, audit) went smoothly — audit-code caught 5 real findings (fire-time resolution, N+1 reads, unstable sort, iOS session-only caveat, an unfixable test-notification edge case), 4 fixed in-PR.
- Smoke-testing the actual feature on-device paid off immediately: it surfaced a genuine separate bug (HAB-229, stale OS notifications after a debug seed re-run) that no amount of code review would have caught.

**What was hard or surprising**
- Running on a real iOS device over wireless debugging was unreliable and heavy: a `flutter run` got stuck on "LLDB is taking longer than expected," eventually failing with `CoreDeviceError`, and separately the MacBook hit ~105°C during iOS build/run activity (tracked for investigation as HAB-230).
- Two separate `git add -A` calls on this feature branch swept in unrelated pre-existing working-tree files (`devtools_options.yaml`, a leftover HAB-226 investigation test) into the PR, each needing a cleanup commit.

**What to change**
- `skills/run/ios/SKILL.md` now prefers a booted Simulator first, skips wireless-only physical devices entirely (falls back to Simulator instead), and requires explicit user permission before handing off a run on a wired physical device.
- `docs/CODE_STYLE.md` gained a "Git hygiene" section: check `git status` before the first `git add -A` on a new feature branch, stage explicitly rather than `-A` when unrelated working-tree state might exist.
- Opened HAB-230 (iOS build/run resource usage research) and HAB-231 (research: migrate ticket tracking off Linear) as follow-ups.
