# HAB-269: Mark a showup done via Siri voice command

## Notes

### 2026-09-07

**WU scope summary** (written at plan approval, per `docs/workflows/plan`'s step 5.5 — refer back here after context compaction instead of re-deriving scope from chat history)

- **WU0 (Checklist-WU, no branch/PR)** — feasibility spike: confirm on a real device that a backgrounded/killed-app `AppIntent` (no `openAppWhenRun`) actually runs reliably, confirm `getDatabasesPath()`'s iOS path is stable enough for Swift to open the same SQLite file, confirm Siri's spoken confirmation flow works truly hands-free. This is the gate for the whole "direct SQLite from Swift, no headless Flutter engine" architectural bet — see the plan comment on the issue.
- **WU1 — native data layer + App Intents** (`feature/HAB-269-WU1-intents`): `VoiceShowupStore`/`VoiceShowup` (raw `sqlite3` reads/writes, mirroring `BreakDerivation`/`ShowupStatus` logic literally), `TodaysShowupsIntent`, `MarkShowupDoneIntent` (full 4-case matching/confirmation flow), `HabitLoopShortcuts` phrase registration. Inert in production — `voice_mark_done_enabled` defaults `false` and nothing writes it yet, so the native `UserDefaults` read is always `false` until WU2.
- **WU2 (final) — feature flag, refresh signal, analytics** (`feature/HAB-269-WU2-flag-signal`): `VoiceRemoteConfigBridge` (Dart RC fetch → native `UserDefaults`), `VoiceWriteSignalListener` (Darwin notification → `dashboardRefreshSignalProvider`), native `FirebaseAnalytics` calls for `voice_today_showups_queried`/`voice_mark_done_resolved`/`showup_marked_done(source: voice)`, flips `voice_mark_done_enabled` to `true`.

Full architectural rationale (why direct SQLite over a headless Flutter engine, how the feature flag reaches Swift, the Darwin-notification refresh bridge) lives in the plan comment on the Linear issue, not duplicated here.

### 2026-09-08

**Case 4 should use requestDisambiguation, not custom parsing**

WU1's case 4 (no match) should use AppIntent's requestDisambiguation(among:dialog:) to list today's remaining showups and let the user pick by position ("the first one") — native Siri disambiguation UX, not custom parsing. Confirms/refines the existing case-4 spec, no new scope.

**Deferred: re-test killed-app Siri case against Release build**

Deferred — re-test Siri "app killed" case against a Release build (not Debug) to check whether the "spinner then silence" symptom is actually the Debug-only crash tracked in HAB-271, not a real background-execution-budget problem for the App Intent itself.

**WU1 audit findings folded in directly** (2026-09-08, PR #444 review): `AppIntents.framework` needed explicit weak-linking (`-weak_framework` in `OTHER_LDFLAGS`) since the deployment target is 15.0 but the framework is iOS 16+ — `@available` alone doesn't stop Swift's hard autolink from crashing dyld pre-`main()` on iOS 15. `VoiceShowupStore` now always opens read-write (even for reads) since a read-only connection can fail to read a WAL-mode db needing `-shm` init/`-wal` replay — exactly the cold-launch case this feature targets; also added `sqlite3_busy_timeout`, `SQLITE_TRANSIENT` on the bound id, an `AND status = 'pending'` guard plus a real `sqlite3_changes` check on `markDone`, and dropped `@MainActor` from both `perform()`s (synchronous SQLite I/O, no UIKit touched).

**WU2 must-close gaps, not deferred to a future ticket** — surfaced by the same audit pass:
- `pact_breaks` is still unchecked by `VoiceShowupStore.todaysOpenShowups` — contradicts the existing in-app rule (`showup_detail_content.dart`, HAB-213) that hides Mark Done for on-break showups. Must be closed before WU2 flips `voice_mark_done_enabled`, not left as a permanent gap.
- Native mark-done doesn't cancel the showup's pending reminder/deadline/hurry-up notifications (the Dart path does, via `cancelRemindersForShowup`) — without this the user gets nagged about something they just told Siri they finished. Needs a plan for WU2 (or a fast-follow ticket if it can't fit WU2's own scope).
- `todaysOpenShowups` has no window-end filter, so a showup whose window lapsed without yet being auto-failed by the Dart-side reconciliation pass still reads back as "today's remaining" — same class of gap as the `pact_breaks` one above, same close-before-flip requirement.

Siri dialog/phrase strings are hardcoded English despite the app shipping en/fr/de/ru — flagged as a suggestion, not a blocker; tracked as a follow-up rather than folded into WU2, since it needs new native `.strings` infrastructure, not just a code change.
