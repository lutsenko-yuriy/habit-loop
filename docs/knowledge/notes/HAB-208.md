# HAB-208: Stop pact: showups wiped entirely and break banner stays after stopping

## Notes

### 2026-07-31

**PactTransactionService's atomicity boundary stops at pact_breaks**

`PactTransactionService`'s own docstring scopes it to atomic writes spanning `pacts` and `showups` only. `stopPact`'s break resolution (`PactBreakService.stopBreak`) is a separate, non-atomic write issued after `stopPactTransaction` completes. A crash between the two leaves a stopped pact with an unresolved break, but it's self-healing: the break banner's visibility and its "Resume pact" button are derived purely from the break's own `stoppedAt`/`plannedEndDate`, independent of `pact.status` — tapping it again resolves the break correctly even on an already-stopped pact. Decided to leave this as a known narrow gap rather than extending `stopPactTransaction` to cover `pact_breaks` atomically, consistent with `PactBreakService`'s own writes (`updateBreak`/sync/cache/reminders) already not being atomic with each other either. Candidate follow-up if this ever needs tightening: pass an already-computed `PactBreak.stop(now)` into `stopPactTransaction` so pact status + showup pruning + break resolution commit together.
