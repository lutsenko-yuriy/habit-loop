**Research-WU findings: Claude Code hook behaviour (CLI 2.1.285)**

Sources: the [hooks reference](https://code.claude.com/docs/en/hooks), plus 5 headless `claude -p` runs in a scratch repo with a committed `.claude/settings.json`, logging every hook input.

| Question | Result | Evidence |
|---|---|---|
| Does a hook see custom slash commands? | **Yes, through a dedicated `UserPromptExpansion` event** (`expansion_type: slash_command`, `command_name`, `command_args`, `command_source`). It fires *before* `UserPromptSubmit`. Exit 2 blocks the command, and `UserPromptSubmit` never fires for it. | T1/T2: `/hello2` was blocked with "Original prompt: /hello2" |
| Do model-invoked skills go through PreToolUse? | Yes: `tool_name: "Skill"`, `tool_input: {"skill": "<name>"}` | T3 |
| Does PreToolUse `deny` hold under `bypassPermissions`? | **Yes.** The Write was refused and no file was created. | T4 |
| Do hooks fire for subagent tool calls? | Yes, with `agent_id`/`agent_type` set. The Agent call itself also reaches PreToolUse (`tool_name: "Agent"`). | T5 |
| Is `${CLAUDE_PROJECT_DIR}` expanded in a committed `settings.json`? | Yes, in hook command strings (docs and every run) | T1–T5 |
| Deny output shape | `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"…"}}`; also allow/ask/defer | docs, T4 |
| Failure semantics | **Any exit code other than 2 fails open.** A crash, a missing interpreter or invalid JSON lets the action through. Default timeout is 600 s, or 30 s for UserPromptSubmit. | docs |

Plan adjustments for WU4/WU7:
1. **Gate slash commands on `UserPromptExpansion` keyed on `command_name`**, not by parsing `/name` out of `UserPromptSubmit`. Drop the planned `UserPromptSubmit` row. `UserPromptSubmit` also receives `<task-notification>` payloads as prompts (T5), so text-parsing it would be fragile.
2. **"Fail closed" has to be explicit.** The bash wrapper must turn any Python failure (non-zero exit, missing `python3`, timeout) into `exit 2` or a deny JSON for PreToolUse, and into exit 0 for `UserPromptExpansion` (fail open, so `/onboard` can't be locked out). Add a test that simulates a crashing `gate.py`. Set an explicit short `timeout` (5 s) so a hang doesn't sit at the 600 s default.
3. Gating the `Skill`, `Agent` and subagent tool calls via PreToolUse works as planned. Subagent calls carry `agent_id`, so the same policy covers them.

**WU3 shipped (YAB #17): 3 audit rounds, 11 findings, 10 of them real write/exec bypasses**

- **Debrief, root cause:** every bypass came from matching exact flag tokens while the tools themselves parse with getopt/pflag:
  - grouped short flags (`sort -ro out`);
  - shortened long options (`--out`);
  - brace expansion (`{-o,out}`);
  - a value flag that consumes `--` (`sort -T -- -o out`);
  - BSD `uniq` treating a second file argument as its output file.

  Lesson: when allowlisting a CLI, model the tool's real argument parser (clusters, abbreviations, `--`, operand positions) before writing per-flag rules, and verify each deny against the real binary.
- **Residuals, documented and not blockable from the command line:**
  - repo config can make git run a program: `diff.external`, textconv filters and `core.fsmonitor`;
  - unquoted globs could match files named like flags.

  Over-strict on purpose: a quoted `{}` (jq object literals) and `git diff --text` are denied.
- **WU4 input:** `is_allowed(command) -> (bool, reason)` is pure; gate.py wraps it in the PreToolUse Bash row.

**WU4 shipped (YAB #18, 9c360b6): 2 rounds, 8 findings + one 🟢 in round 2**

Round 1 found 3 🟡 in the fail-safe design itself, not in the policy:
- a missing `gate.py` makes CPython exit 2, which reads as a deliberate block;
- a hook timeout fails open;
- the payload `cwd` follows a Bash `cd`.

The fixes:
- `gate.py` blocks with its own exit 10, which `gate.sh` maps to 2;
- `gate.sh` runs a 3 s watchdog;
- the root comes from `CLAUDE_PROJECT_DIR` first.

Debrief lesson: when building a fail-closed wrapper, enumerate every way the host can see a "success" or "block" signal that the wrapper didn't intend: interpreter exit codes, timeouts, cwd drift.
