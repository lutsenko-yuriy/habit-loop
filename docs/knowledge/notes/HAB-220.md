### 2026-08-24 — correction to the baseline (WU1's own script caught this)

Building `scripts/docs/context_cost.py` (WU1) surfaced two bugs in the plan's original 10,676w baseline, found by diffing the script's output against this session's own real rendered system prompt:

1. **`@`-includes are not whole-line-only.** `AGENTS.md`'s `Details: @docs/VERSIONING.md` (plain prose, no backticks, not a standalone line) *does* expand — it rendered in full at session start. The original audit's whole-line-only assumption silently missed it, which is why `docs/VERSIONING.md` (3,068w) was absent from a first buggy run of the script.
2. **Recursion is capped at depth 2 from `CLAUDE.md`, not unlimited.** `CLAUDE.md` -> `@AGENTS.md` (hop 1) -> AGENTS.md's own `@`-includes, e.g. `@docs/VERSIONING.md`/`@docs/workflows/FEATURE.md` (hop 2), render in full — but *those* files' own `@`-includes (e.g. `FEATURE.md`'s `@skills/shared/decision-guidelines.md`, at hop 3) do **not** expand; they appear as literal, un-expanded `@path` text in the rendered session. Confirmed by reading this session's own actual system-prompt content, not inferred from documentation.

**Net effect: `skills/shared/decision-guidelines.md` (582w) and `skills/shared/wu-splitting-guidelines.md` (295w) are *not* part of fixed cost today, contrary to the original plan text.** They're currently variable cost only — paid when a skill's own `SKILL.md` pulls them in directly (most skills do). The corrected, script-verified baseline is **9,800 words / ≈13,230 tokens** (was wrongly stated as 10,676w/≈14,400 tok).

This does **not** kill WU3: `docs/VERSIONING.md`'s CI-ops content (~2,168w removable), `TROUBLESHOOT`/`RESEARCH`/`POSTMORTEM` (1,269w, still genuinely hop-2 fixed cost), and `FEATURE.md`'s own Multi-WU appendix text (622w, measured directly — excludes the `wu-splitting-guidelines.md` file it points to, which was never fixed cost to begin with) are all still real, still-fixed, removable content. Recomputed: (2168+1269+622)/9800 ≈ **41%** — the ≥40% Checklist-WU target still clears, but narrowly; if any of WU2/WU3's cuts land smaller than estimated the target should be re-verified with the script rather than assumed.

The Linear plan comment on this ticket still states the original, now-superseded 10,676w figure and the "decision-guidelines.md is fixed cost" claim — flagged as stale there; this note is the corrected source of truth going forward.

### 2026-08-24 — WU1 review/audit fixes

`review-architecture` and `audit-code` both independently caught the same core bug in `context_cost.py`'s `resolve_includes`: it used depth-first "seen once ever" visiting, so a file first reached through a *longer* path got marked done at that depth, silently blocking a later *shorter* path to the same file from being (correctly) explored further within the depth cap. Rewrote it as breadth-first search keyed on first-discovery depth — a node's recorded depth is now always its true shortest distance from the start, independent of declaration order. Regression test: `test_shortest_path_wins_regardless_of_declaration_order`.

Also fixed, all from the same two review passes:
- Triple-backtick fenced code blocks weren't excluded (only single-backtick spans were) — two skill files had `@skills/<path>/SKILL.md` inside a fence, producing bogus "missing include" noise. Now stripped before line-splitting.
- `render_variable_section` silently discarded broken includes found while walking `skills/**` — restored, mirroring the fixed-cost section's own "Broken includes" reporting.
- `@` regex had no left boundary, so `me@example.md` or a URL fragment like `.../y@docs/E.md` could false-positive as includes. Added a `(?<!\w)` guard.
- `--skill <typo>` printed an empty table and exited 0; `--fixed-only --skill x` silently dropped `--skill`. Now: unknown skill name errors loudly (exit 2), and the two flags are a proper mutually-exclusive argparse group.
- `_display_path` (`relative_to`) could raise uncaught on a path genuinely outside `repo_root` (e.g. an out-of-repo symlink target) — now falls back to the absolute path instead of crashing the whole report.

Two findings were judged non-bugs and documented instead of "fixed": (1) the 9,800w baseline isn't reproducible across machines because it includes gitignored, per-machine `CLAUDE.local.md` — genuinely true, not fixable, now stated explicitly in the script's own docstring; (2) the depth-2-from-`CLAUDE.md` cap is this repo's best available model but a competing hypothesis (path resolved relative to the containing file, not a hop-count cutoff) fits every observation here equally — flagged in the docstring as something to re-verify if a future include graph shape distinguishes the two theories.

Baseline word counts are unaffected by any of these fixes (all bugs were in paths not exercised by the current, still-small include graph). Re-running `python3 scripts/docs/context_cost.py --fixed-only` on this machine after the fixes gives 9,761w/≈13,177 tok — a few dozen words off the 9,800w figure quoted above, because `CLAUDE.local.md`'s exact content (gitignored, edited between the two runs) is per-machine and not reproducible, as the script's own docstring now says explicitly. Treat "≈9,800w, ≈41% clearable" as the right order of magnitude, not an exact figure — re-run the script for the current number rather than quoting either of these.
