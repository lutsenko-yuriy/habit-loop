# HAB-241: Stop CI pushing build-number commits to main; require PR + enable branch protection

## Notes

### 2026-08-17

**Code comments should default to concise/schematic style**

A code comment added to `release.yml` (explaining why the tag push is now the sole
record of build-number consumption) ballooned to 13 lines of full-sentence prose
before being trimmed to 6. Comments during `/implement` should default to the
shortest text that keeps the sense and stays readable — concise-to-schematic, not
full CONCISE-style prose. Worth codifying in `docs/CODE_STYLE.md` or the implement
workflow's comment-hygiene guidance.

### 2026-08-17

**PR comments and notes should sit between CONCISE and DETAILED**

Separate calibration from the code-comment note above: PR comments (review/audit
findings, replies) and knowledge-base notes should carry enough context that a
reader doesn't need the backstory, but shouldn't collapse to the one-liner style
used for chat replies. First trimmed-too-far in a PR reply, then corrected here —
worth distinguishing explicitly from the concise/schematic code-comment guidance.
