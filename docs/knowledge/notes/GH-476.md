# GH-476: Migrate integration scenarios to test robots

## Notes

### 2026-10-14

**Repeated "use the robot everywhere" review findings**

Almost every WU's architecture review flagged that a robot getter or method existed but a scenario (often one merged in an earlier WU) still spelled the step out by hand. Adding the rule to the implement-subagent prompt at WU7 reduced it, but WU9's final review still found leftovers across previously-migrated files.

**Uncounted shim callers**

WU9 discovered 39 remaining calls to the transitional harness delegates in files earlier WUs had already migrated; the plan only assigned each WU its own scope files.

**Subagent incidents**

A WU4 implement subagent ran `git stash` / `git stash pop`, applied an unrelated old stash and had to restore two files from HEAD. A nested `$(cat <<'EOF')` with an apostrophe garbled one PR body (use `--body-file`). `gh run watch` exited early once; a status-polling loop was reliable.

**User correction**

WU1: "the comments are way too wordy" on comments copied verbatim into robots; one-line rule then stated in every subagent prompt plus a diff skim before pushing.

## Debrief summary

### 2026-10-14

**What went well**
- The whole 9-WU migration ran autonomously after the user granted merge authority at WU4 (merge on green CI + addressed reviews); the user was happy with the result.
- Every WU's scenarios CI run was green once review fixes landed, including all keyboard-workaround deletions — none had to be restored.

**What was hard or surprising**
- Review churn: most WUs needed a fix-and-redispatch cycle for "robot step exists but scenario inlines it". Not very visible to the user, but extra work.
- WU9 had 39 uncounted delegate callers left in already-migrated files.

**What to change**
- `draft-scenarios` now reads the robots, tags every UI step with the robot that performs it (marking missing actions `(new)`), and keeps the tags in the `// TODO:` stubs, so `implement` extends robots instead of inlining steps.
- Robots guidance moved into the shared "Harness usage" row in `skills/shared/project-config.md`, read by both `implement` and `draft-scenarios`.
