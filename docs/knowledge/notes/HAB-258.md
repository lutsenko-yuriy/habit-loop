# HAB-258: Flaky pact-note/timeline write-through scenarios in scenarios.yml

## Notes

### 2026-09-06

**audit-code's subagent invocation silently skipped**

When `review-architecture` and `audit-code` were invoked together for PR #440, `review-architecture`'s routing message inlined its full `SKILL.md` content directly (executed inline, correctly). `audit-code`'s routing message instead came back as a short "route this to a subagent — read the skill file, spawn an Agent" instruction. The Agent call for `audit-code` was never actually made — only the routing instructions were read — and the gap went unnoticed until the user asked for a status update and it turned out no such agent existed (checked via `ListAgents`). The user says this happens often, not a one-off. Possible cause: the two routing message formats look different enough (one is fully inlined skill content to follow directly, the other is meta-instructions to act on) that when both arrive back-to-back, the second one's "go do a thing" framing doesn't register as distinctly as an action item compared to the first one's "here's content to follow now." Worth a debrief-time look at whether the routing/dispatch step needs a more forcing structure (e.g. always confirming each spawned agent's ID back before proceeding) so a skipped spawn is caught immediately rather than discovered on follow-up.

## Debrief summary

### 2026-09-06

**What went well**
- Each fix was grounded in a specific, observed CI failure rather than speculation — diagnostic prints were added and validated live before forming a new hypothesis, instead of guessing twice from code reading alone.
- Splitting off the residual, still-not-fully-understood flakiness into a separate ticket (HAB-267) rather than blocking this PR indefinitely on it.
- The audit-code review caught a real bug I'd introduced in my own "fix" (a `pumpAndSettle()` call that hung indefinitely) before it reached CI, and a genuine gap (`waitFor` with no corresponding wait for the old text to disappear) that's a plausible real cause of the residual flakiness.

**What was hard or surprising**
- The whack-a-mole nature of it: fixing one confirmed race in `pact_note_flow_test.dart` reliably surfaced a *different* one on the next dispatch, across roughly ten CI cycles. The friction wasn't the individual fixes — it was discovering, each time, that "fixed" only ever meant "this specific failure mode is gone," not "the file is stable."
- No architectural user-facing lesson emerged from the pattern itself — it just confirmed that this class of instability (CI-only, timing-sensitive, one file with many timing-sensitive touch points) needs a systemic fix, not more one-off patches.

**What to change**
- Follow-up: prioritize HAB-200 ("test robot" abstraction for integration scenarios) as the systemic fix — a shared, tested helper library would prevent the whole class of bug seen here (missing settles, ambiguous state polling, silent timeouts) from being re-invented per-file.
- Process fix applied directly: `docs/workflows/FEATURE.md` step 10.1 now requires confirming a routed review skill's subagent actually spawned, since that gap (routing instructions read but the Agent call itself skipped) recurred this session and, per the user, happens often.
